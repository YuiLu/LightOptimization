# Lighting MVP — Unity native RGB optimizer

The editor plugin optimizes existing realtime Point and Spot Lights against the **actual RGB output of the selected Unity scene cameras**. It uses the current URP asset, each camera's own renderer and renderer features, original materials, native shadows and configured post-processing. The plugin does not use irradiance, an analytic forward model, Python, Mitsuba, or an external renderer.

## Install and use

Use Unity 2022.3 / URP 14. Copy this source folder into an existing Linear/HDR URP project if needed; sample scenes and pipeline assets are not part of the source-only repository.

1. Open **Lighting MVP > Optimize Lighting (Unity RGB)** in Edit mode. Add one to four standalone Base cameras and one to eight enabled realtime Point or Spot Lights. Use **Use main camera / Use selected lights** as shortcuts.
2. **Capture current rig as target**. The plugin warms up each camera once, then compares two captures of the same state and rejects unstable frames. Keep cameras, geometry, material/volume settings, other lighting and pipeline fixed from capture through solve. Recapture after editing any of these.
3. Change your lights manually or use **Seeded perturbation (Undoable)**. The position distance is in world units; intensity changes multiplicatively. Check **Fit hue and saturation** to include two color coordinates per light (the starting HSV value is fixed). Choose a position search extent and log intensity factor relative to each **starting** light; widen these if the desired solution falls outside them. Spot aim uses two bounded tangent-plane coordinates around each starting direction; set **Spot aim ± per axis (°)** to adjust the search extent. Aim the cone at camera-visible surfaces before fitting. Use standalone light transforms; moving a light must not also move geometry, a camera or another light.
4. **Start / re-run optimization**. Default is Central FD + L-BFGS. Select **Image Jacobian + LM** for the fixed-color experiments below, or **SPSA + Adam** for comparison. LM caps residual/Jacobian buffers at 192 MiB; lower the resolution or the number of cameras/lights if needed. The render budget counts actual training camera renders (e.g. one two-camera loss costs two renders). Target capture (including one complete warmup), sensitivity probes, repeat checks and best re-captures are reported separately. Cancel or an error restores the starting light parameters.
5. Compare **Target / Before / Best re-capture** and all-views RGB NRMSE. Replay best-so-far states with **All lights** or **Selected light only**. The solo preview mutes only the other fitted lights for that capture, not the rest of the scene, and does not affect the fit score. **Apply best rig to scene (Undoable)** is the only operation that applies an optimized state. Light types, Spot cone angles, range, layers, shadow settings and temperature controls remain unchanged.

Capture reads a float, linear RGB offscreen target at the chosen long edge and camera aspect (rounded to integer pixels). The preview uses a fixed display curve; the loss uses the original RGB, not the preview. This is a fixed-resolution render request, not a grab of the Game View or of an external image. Use standalone HDR cameras with full viewport; stacking, XR and dynamic resolution are outside this MVP. Camera post-processing is preserved; a tone-mapper may intentionally compress values before capture. Turn off history-dependent effects such as TAA, and freeze animated state. A Spot with no measurable RGB response needs to be re-aimed toward visible geometry before fitting; decreasing the finite-difference step cannot recover an unobserved light. The plugin checks repeatability, light response, and best re-capture; it does not silently skip incompatible renderer features or switch pipelines. A shader or volume with no response to the selected realtime lights cannot be optimized through those lights.

## Irradiance is debug only

- **Lighting MVP > Debug > Native Irradiance Preview** captures material-independent URP direct lighting on supported opaque geometry, with an eye-depth view. Use a scene camera or the Scene view pose. The optional temporary test light is diagnostic only. Supports non-Cornell scenes including Mar7thRoom; the sensor is not a measure of its custom deferred shading, TAA or other final appearance.
- **Lighting MVP > Debug > Legacy field and replay** inspects old Cornell field outputs and plays back multi-light recordings in all-lights or selected-light mode. Turn off/close its scene overlay or replay before a new RGB capture. No analytic fitting menu is exposed; historical implementations are retained for comparison.

## Run benchmarks

Use a GPU-enabled Unity batch session (`-batchmode`, **not** `-nographics`) and a separate project copy if the main editor is open. Methods exit with a nonzero code on failure. The Cornell benchmark requires `Assets/Scenes/CornellBoxMvp.unity` and the local URP HighFidelity pipeline/renderer assets.

- **Workflow smoke tests:** `-executeMethod LightingMvp.Editor.BlackBoxLightingSmoke.BatchCornell` or `LightingMvp.Editor.BlackBoxLightingSmoke.BatchMar7thRoom`, or `LightingMvp.Editor.BlackBoxLightingSmoke.BatchMixedLm` (two cameras and a fixed Point + Spot rig). They check native camera callbacks, render accounting, RGB improvement, cancellation/error restoration, solo replay, apply and undo. The Cornell smoke uses the existing HighFidelity Forward asset including its renderer features; the room test uses its own custom renderer and a test-only fixed interior camera/point rig and explicitly disables custom TAA for the test. Neither test saves the scene.
- **Research E0–E3:** `-executeMethod LightingMvp.Editor.NativeRecoveryExperiment.BatchRun -bbCase <case> -bbSeeds <1–5> -bbOutput <directory>`. Cases: `smoke`, `e0`, `e1`, `e2-fixed`, `e2-lit`, `e2-stylized`, `e2-stylized-fixed`, `e2`, `e3`, `diagnose`, `all`. The controlled Cornell runner uses a temporary stock Forward configuration, unlike the plugin. In the staged suite full-color E2 requires the fixed-color gate; use one seed for the separate engineering smoke and `e3` for the independent view check. Training is 256²; high-resolution validation is 512². Run `python mvp/blackbox_report.py <directory>` from the repository root for curves and summaries.
- **Research E4–E6:** use the same `BatchRun` entry with `-bbCase e4`, `e5`, then `e6`, all with the same new `-bbOutput` directory. The fixtures and seeds are fixed; omit `-bbSeeds`. E5/E6 read `e4_decision.json` (or accept `-bbLocal CentralLbfgs|ImageJacobianLm`). Run `python mvp/blackbox_next_report.py <directory> --baseline docs/blackbox/trials.csv` to audit the paired render ledger and export `trials.csv`.
- **Research E7–E8:** use `-bbCase e7` then `-bbCase e8`, with the same `-bbOutput`. E7 measures native HDR response and selects OLAT or actual intensity-grid screening for E8. E8 compares paired random, Multi-start, insertion, and insertion + Swap runs in Cornell Lit; these are research entry points, not changes to the interactive plugin defaults. See the linked report for budget, held-out view, and ledger verification.
- **Research E9–E11:** `e9` and `e9-probe` read the Cornell Lit E7 gate. `e10`, `e10-near`, `e11-smoke`, and `e11` use the publicly sourced Classroom fixture with all seven authored Point Lights. See the linked report for fixture conversion, stage gates and query accounting.
- **Optional offline ZeroGrads comparison:** cases `zerograds` and `zerograds-stylized` accept `-bbPython <Python with PyTorch> -bbZeroGradsModels <trusted models.py>`. If necessary pass `-bbZeroGradsAdapter <absolute path to mvp/blackbox_zerograds.py>`. The tested [official revision](https://github.com/mfischer-ucl/zerograds/tree/7490db85e5c6524aa1a8844913449334b7781d0f) declares MIT in its README and is not vendored. Python receives only candidate coordinates and scalar Unity loss; no external rendering or dependency is part of the plugin.
