# E24 · Unity 原生有效可见性与灯光恢复

E24 对照 E23 的两个失败起点，检验无阴影时的可恢复性，以及原生 RGB 强度响应估计的可见性是否能改善位置更新。目标、探针和验收图都由 Unity URP 生成。活动灯联合更新 `XYZ + log(I)`；灯数、颜色、Range、材质及相机固定。

## B/C · 有效可见性与锚定差分

在 54 个 Complex、18 个 Classroom 的灯–视角审计中，低 Off 响应像素的中位比例分别是 **27.12%、28.01%**；Classroom 最高一组达 96.52%。未裁剪比值略大于 1 的像素中位比例为 13.68%、15.88%，但 RGB 响应拟合的相对 L2 残差中位数仅为 `2.39e-6`、`1.17e-6`。`0.02` 对 `0.04 log(I)` 的 mask 平均绝对差的中位数为 `7.30e-6`、`1.29e-5`；把低响应阈值提高到 `1e-2` 时，两者都变为约 0.022。信号在已测强度步长下稳定，但遮挡先验的有效覆盖仍取决于 Off 响应。

表中是三种合法步长比例上、两次复拍都观察到的最佳目标相对下降；零表示未观测到可重复下降。H4、C4 过门槛的两行是**同一 Far seed 的两个终点**，不是两个独立扰动。C3 在四个失败状态上过门槛。C1 对同为 Raw 的 H0 没有一次过线；H5 的条件未满足。

20 mm 时，Complex 的位置列与完整 Hard 链式列的余弦中位数为 H2 `0.280`、H4 `0.348`、C3 `0.290`；Classroom 分别为 `0.783`、`0.887`、`0.818`。Classroom 的单列更接近 Hard 列，却没有带来失败终点的实际下降，说明列一致性与整步收益不能互换。Complex 未加 mask 的负 HDR 代理像素比例中位数为 0.215%，加 mask 后中位数为 0；差分保留有符号值。

| seed157 | ✓ · 4,644 | ✓ · 4,689 | ✓ · 4,677 | ✓ · 4,479 |
| seed733 | ✗ · 4,659 | ✓ · 3,081 | ✓ · 4,725 | ✓ · 4,551 |
| dir793 · 5 cm | ✓ · 2,982 | ✓ · 1,974 | ✓ · 1,977 | ✓ · 1,977 |

每臂共享 4,725 张预算，按 75%/25% 分配辅助与精修预算；三个 Near 入口均因连续三次候选拒绝且信任域已经缩小而提前切换，分别在第 1,323、2,856、885 张相机图之后。D2 保留 Log 目标；D3 重建 Raw 残差并重置信任域和阻尼。5 cm 的已记录 D2/D3 在辅助阶段近零终止后仅各多做一次三视角查询，灯阵未再更新；发布 runner 遇到近零直接结束。

D2 保住了 4/4 的参数通过率，但 seed131 / 733 的留出显示 NRMSE 分别从 0.068% / <0.001% 升到 2.84% / 0.79%。D3 改善了 seed157 的留出显示误差并少拍 210 张，却让 seed131 的最大位置误差升到 **9.37 cm**。切换收益依赖起点；没有任何切换臂同时保住 C4 的通过和留出表现。

## E · 独立方向与扰动尺度

用 Unity 世界坐标欧氏距离设置扰动，同一方向内各半径共用每灯单位向量；常规起点交替施加 `±0.05 log(I)`。20/30 cm 为 1,560 张筛选，扩展到 50 cm 用 4,725 张。E23 的 2/5/10 cm 数据单列在 `stage-summary.json`，不与本机结果混算。旧 Complex 方向 271、793 在 20/30/50 cm 全部合法，只选择 793 加入这轮 20/30 cm；新方向 911、1201 均按 20/30/50 cm 同时合法筛选，每个方向七灯合计接受 7/13、7/19 次采样（分母包含球内拒绝采样和合法性拒绝）。这些是条件合法方向，不代表无条件采用的随机初值。

| 场景 · 位移 | 方向 | H0 · Raw On | H2 · B2 | C4 |
|---|---|---:|---:|---:|
| Complex · 20 cm | 793、911、1201 | 0/3 | 0/3 | **1/3** |
| Complex · 30 cm | 793、911、1201 | 1/3 | 1/3 | **2/3** |
| Complex · 50 cm | 911 · 4,725 张上限 | 1/1 | 1/1 | 1/1 |
| Classroom · 10 cm | 1301、1601 | 0/2 | 0/2 | 0/2 |
| Classroom · 20 cm | 1301、1601 | 0/2 | 0/2 | 0/2 |
| Classroom · 30 cm | 1301、1601 | 0/2 | 0/2 | 0/2 |

Complex 的两个独立新方向中，C4 恢复了 `1201 / 20 cm` 和 `1201 / 30 cm`，但 `911 / 20 cm` 留出显示 NRMSE 为 **14.57%**，高于 H2 的 3.04%；不能把筛选种子上的 3/3 当成普遍收敛率。把 `911 / 30 cm` 的强度扰动提高到 `±0.25 log(I)`，三臂都不通过；C4 最接近通过线，最大误差由常规扰动的 `4.96 cm / 5.38%` 变为 `5.43 cm / 5.41%`。同一方向的两个半径不是独立样本。

Classroom 的独立方向 1301、1601 在同一灯位置单位方向下通过 10/20/30 cm 合法性检查，七灯分别接受 7/23、7/22 次采样；18 个优化试次无一达到全灯门槛，50 cm 条件未启动。单列的原 E23 seed509 Near（约 23–30 cm，各臂最高 4,725 张）也全部失败：C4 的最大误差 `45.60 cm / 27.50%` 小于 B2 的 `63.49 cm / 31.34%`，留出显示 NRMSE 却从 22.79% 增至 24.31%。

Complex 的 `911 / 50 cm` 在 4,725 张验证上限内三臂均通过，实际拍摄 H0 3,771、H2 3,999、C4 3,741 张；三个终点的留出显示 NRMSE 均小于 0.05%。该结果只覆盖一个方向，且预算高于 20/30 cm 筛选，不能解释为 50 cm 更易恢复。

## 结论

Unity 原生 RGB 足以在部分七灯复杂起点验证新位置模型的真实收益。C4 在 Complex 的开发样本增加了一次七灯恢复，独立方向也增加了恢复，但没有推及 Classroom。关闭阴影仍重现两场景的失败，因此现有结果不支持“阴影变化是唯一瓶颈”；Classroom 的 L6 单灯 Oracle 也未恢复。D 的切换没有带来一致改进。本轮没有获得能把失败归到代理可补充可见性分量的对照证据，未启动 Moment。

## 方法和口径

- **固定目标。** Hard 各臂均以同一 Hard GT 复拍和验收。A 的 Off GT、4D 其余灯固定在 GT 都是合成 Oracle，独立计量；Off 终点另用 Hard GT 复拍，未参与搜索。
- **信号。** H4 在每次 Jacobian 以同一个合法 log(I) stencil 拍摄 Hard/Off；其他灯全部开启。Hard 侧同时给真实 Signed Log 强度列。RGB 最小二乘比例只乘该灯三条位置列，再乘 Hard 锚点的映射导数。默认阈值取每灯每视角 `P95(||C_Off||) × 1e-3`（下限 `1e-12`），`ε=max(1e-30,10⁻⁶×阈值²)`；低响应或不可信像素回退 1。后者为强响应像素上 RGB 余弦小于 0.95、裁剪后相对残差大于 20%，或原始比例超出 `[-0.05,1.05]`。每次模型重建重新估计。`1e-4 / 1e-2` 阈值和 `0.02 log(I)` 仅用于审计。
- **对照。** H0 为 Raw 完整 Hard FD，H1 为 Signed Log 完整 Hard FD，H2 为 Off 位置列乘 Hard 映射导数。C1 为 Raw + Off 位置列，C3 对 `Hard anchor + Off(q) − Off anchor` 直接做 Signed Log 差分，C4 对 Off 增量乘 mask 后锚定。H5 为 masked Off 与链式 On 各半，不把差值解释成纯物理可见性导数。
- **搜索。** `LampScaledDense`、Strict Collider、默认 XYZ 20 mm 和 log(I) 0.04，信任域起值 0.24 m / 0.28 log(I)，沿用实际下降与 `rho` 验收。方向比较共用起点、初始阻尼和信任域；在同一合法候选位移的 `¼、½、1` 倍各重复复拍两次。Raw 和 Log 只在同映射内比较。
- **预算。** 筛选上限 1,560 张三视角优化相机图，验证上限 4,725。On/Off anchor、探针、候选均记账；GT、独立诊断、初末复拍单列。优化为三个 `448×256` 视角；复拍为三个同视角加两个留出视角 `896×512`。Raw HDR、Signed Log 和 Tone-Exp + sRGB NRMSE 均先逐视角归一化，再做 RMS 汇总。通过门槛为全活动灯 ≤5 cm、相对强度误差 ≤5%、最终合法。
- **资产。** 使用 [E23 基线 `a89669d`](https://github.com/YuiLu/LightOptimization/tree/a89669d68ad6ce3927f7bb1e7bbe250e2100de9e/docs/blackbox-e23) 的原始归一化起点快照。实验机器的 Unity / URP 版本与 E23 相同，GT 灯阵和相机一致；本机两份场景资产与 E23 的原文件 SHA-256 不同。各 E24 匹配臂共享同一份本机资产；`stage-summary.json` 保留两套 SHA、P90、固定起点的 Hard Log 损失复拍。本机数据不与 E23 历史臂混合计分。

## 复现与数据

从仓库根目录运行（PowerShell，把 Unity 路径替换为本机安装位置）：

```powershell
python mvp/blackbox_e24.py --unity 'E:\UnityEngine\2022.3.62f3c1\Editor\Unity.exe' `
  --project tmp/e24-work/project --assets-project Light --output tmp/e24 `
  --pipeline --resume --export docs/blackbox-e24
```

默认要求与 E23 的场景 SHA 一致。若使用本报告中的本机重导入版本，加 `--allow-different-asset-hash`；runner 会保留实际 SHA，并仍校验灯阵、摄像机与渲染版本。`--assets-project` 只复制实验所需资产，复用一个独立工作目录，不复制旧 `Library`。`--stages` 可单独运行阶段，`--models` 供复跑已通过门槛的臂。

- [`trials.csv`](trials.csv)：单臂参数和三种图像误差、合法性、停止原因、实际 On/Off 拍摄量和时间。
- [`stage-summary.json`](stage-summary.json)：阶段门槛、条件臂、环境、GT、资产哈希。
- [`direction-probes.csv`](direction-probes.csv)、[`visibility-audit.csv`](visibility-audit.csv)、[`mapping-fd.csv`](mapping-fd.csv)：方向复拍、强度响应和映射消融。
- [`switch-log.csv`](switch-log.csv)、[`displacement-sweep.csv`](displacement-sweep.csv)：精修切换与各灯实际扰动和采样；未启动的阶段不填伪数据。
- [`raw-data.zip`](raw-data.zip)：数值、快照、逐视角误差、Atlas、求解日志与源码 SHA。`figures/` 仅存代表图。本报告共 89 个优化试次；本机留存阶段 GT、初态和终态的 HDR 复拍，不写优化逐帧图，不提交本地捕获、Unity 缓存或环境文件。GPU 独占时间未能按同步相机调用可靠归因；渲染提交、读回、进程 CPU、墙钟分开记录。
